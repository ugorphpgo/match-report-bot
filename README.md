# match-report-bot

Отбирает футбольные матчи на завтра, ранжирует по приоритету и шлёт в Telegram. Заодно публикует отобранное как `data/{локаль}_{дата}.json`.

Первая половина проекта. Вторая —[coupon-filler— читает эти JSON-файлы и заполняет ими купоны в админке.

Половины связаны **только** этими файлами. Ключ связи — числовые `league_id`, `home_team_id`, `away_team_id`: по ним матч находится в маппингах заполнения. Названия для этого не годятся, клубы переименовываются.

---


Что делает `match_report.py`:

1. Тянет матчи на завтра из Highlightly (с пагинацией).
2. Отсекает стартующие раньше 07:00 по Минску — ночные матчи неактуальны.
3. Донабирает «перетёкшие» матчи Бразилии и Мексики: у них вечер по местному времени приходится по Минску уже на послезавтра.
4. Ранжирует по весам из `config/league_weights.json`.
5. Пишет `data/{локаль}_{дата}.json` и коммитит их в репозиторий.
6. Шлёт отчёт в Telegram.

### Что уходит в Telegram

**Одно сообщение**, а не семь. Global получает полный топ-30, каждая локаль — только матчи своих турниров либо «Местных матчей на эту дату нет».

Так сделано потому, что раньше сообщения дублировали друг друга почти целиком: у Индии, Ирана и Нигерии 29 из 30 матчей совпадали с global. Если суммарный текст не влезает в лимит Telegram (4096 символов), он разбивается **по границам локалей**, а не посреди списка.

В `data/*.json` при этом лежит полный список по каждой локали — виджеты в админке заполняются целиком.

## Порядок приоритета

Задаётся весами в `config/league_weights.json`. Диапазоны разнесены намеренно:

| Диапазон | Вес |
|---|---|
| Сборные (ЧМ, Евро) | 1 700 000 … 2 000 000 |
| Международные клубные (ЛЧ, ЛЕ) | 800 000 … 1 000 000 |
| Местные топ-лига и кубки | 500 000 … 520 000 |
| Глобальные топ-лиги | 106 850 … 109 900 |
| Вторые дивизионы | 50 000 … 55 000 |
| Всё остальное | 50 |

Чтобы поднять или опустить лигу, правится одно число — код трогать не нужно. Запас между диапазонами большой специально: правка одного веса не может случайно перебросить лигу в соседний диапазон.

Каждая запись хранит название лиги в поле `name` — это данные, а не комментарий, поэтому их видно и в конфиге, и в любых скриптах.

## Переменные окружения

Задаются в Settings → Secrets and variables → Actions:

| Переменная | Зачем |
|---|---|
| `HIGHLIGHTLY_API_KEY` | получение матчей |
| `TELEGRAM_BOT_TOKEN` | отправка отчёта |
| `TELEGRAM_CHAT_ID` | куда отправлять |

Имена должны совпадать точно — workflow обращается к ним как `secrets.HIGHLIGHTLY_API_KEY` и так далее.

Без любой из них прогон остановится с сообщением, какую переменную задать, а не с невнятным `KeyError`.

**Actions в новом репозитории может потребоваться включить** во вкладке Actions — иначе расписание не сработает.

## Локальный запуск

```bash
pip install -r requirements.txt
```

```bash
export HIGHLIGHTLY_API_KEY=<ключ>
export TELEGRAM_BOT_TOKEN=<токен>
export TELEGRAM_CHAT_ID=<id>
python -u match_report.py
```

Флаг `-u` важен: без него вывод буферизуется и печатается одним куском в конце, из-за чего по логам невозможно понять, на каком шаге тратится время. В workflow он уже прописан.

Пути к конфигу и `data/` считаются от расположения скрипта, так что запускать можно из любой директории.

## Диагностика

В логах прогона есть тайминги: сколько заняла каждая страница выдачи Highlightly и каждая отправка в Telegram. Если прогон долгий — по ним видно, где именно.

Запросы к одной и той же дате кешируются на время прогона: донабор «перетёкших» матчей запрашивает послезавтра отдельно для Бразилии и Мексики, и без кеша этот день выкачивался бы дважды.

Ошибка отправки в Telegram больше не проходит молча — прогон падает с кодом ответа. Раньше протухший токен или битый Markdown означали, что скрипт отчитывается об успехе, `data/*.json` коммитятся, а в чат ничего не приходит.
