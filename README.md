# match-report-bot

Отбирает футбольные матчи на завтра, ранжирует по приоритету и шлёт в Telegram. Заодно публикует отобранное как `data/{локаль}_{дата}.json`.

Первая половина проекта. Вторая —[coupon-filler— читает эти JSON-файлы и заполняет ими купоны в админке.

Половины связаны **только** этими файлами. Ключ связи — числовые `league_id`, `home_team_id`, `away_team_id`: по ним матч находится в маппингах заполнения. Названия для этого не годятся, клубы переименовываются.

---


Что делает `match_report.py`:

1. Тянет матчи на завтра из Highlightly (с пагинацией).
2. Отсекает стартующие раньше 07:00 по Минску — ночные матчи неактуальны.
3. Донабирает «перетёкшие» матчи Бразилии и Мексики: у них вечер по местному времени приходится по Минску уже на послезавтра.
4. Ранжирует по приоритетам из `config/league_weights.json`.
5. Пишет `data/{локаль}_{дата}.json` и коммитит их в репозиторий.
6. Шлёт отчёт в Telegram.

### Что уходит в Telegram

**Одно сообщение**, а не семь. Global получает полный список (топ ивенты ≈14 и топ матчи ≈12, целыми турнирами), каждая локаль — только матчи своих турниров либо «Местных матчей на эту дату нет».

Так сделано потому, что раньше сообщения дублировали друг друга почти целиком: у Индии, Ирана и Нигерии 29 из 30 матчей совпадали с global. Если суммарный текст не влезает в лимит Telegram (4096 символов), он разбивается **по границам локалей**, а не посреди списка.

В `data/*.json` при этом лежит полный список по каждой локали — виджеты в админке заполняются целиком.

Рядом со списком в файле лежит **запас** (`reserve`) — следующие по приоритету турниры сразу за обрезом, ещё один Top Matches по размеру, — и цели виджетов (`widget_targets`). В Telegram запас не уходит: им coupon-filler по кнопке заменяет матчи, которых нет в админке, заново деля список с запасом на виджеты тем же правилом. Там же поле `national` — матчи своей сборной локали (взрослой мужской, по точному имени из `LOCALE_NATIONS`), где бы они ни оказались в ранжировании: coupon-filler ставит их первым пресетом Top Events. Каждый матч файла несёт `own_national` — какая сборная страны этой локали в нём играет (`senior`, `youth`, `women`): coupon-filler подсвечивает такие матчи, а младшие и женские поднимает первыми внутри их пресета.

Порядок матчей внутри турнира и пометка топа (карта `.scratch/team-priority/` в coupon-filler): матч может нести `top` (`true` у топ-матча), `top_reason` (`"pair"` — «топ + топ» или «топ + сильная»; `"own_club"` — свой клуб локали в международном клубном турнире) и статусы команд `home_tier`, `away_tier` (`"top"`, `"strong"`, `"regular"`). По ним coupon-filler строит топ-пресет — отдельный пресет турнира над остальными его матчами. Формат зафиксирован заполнялкой (задача 14), бот пишет ровно эти поля; без них заполнялка читает файл как раньше.

## Порядок приоритета

Задаётся приоритетами в `config/league_weights.json`. Обычно их правят не руками, а во вкладке «Приоритеты» заполнялки (coupon-filler): она показывает турниры по категориям админки, подсказывает, между какими турнирами встанет число, и сама коммитит и пушит сюда.

Файл устроен так:

- `priorities` — общий приоритет турнира для всех локалей: `{id: {name, priority, group}}`. Запись без `priority` — турнир, сброшенный к умолчанию: имя и `group` у него остаются;
- `locales.<локаль>.overrides` — переопределение для одной локали: `{id: priority}`;
- `default_priority` — для всех турниров, которых нет в таблице (1);
- `ranges` — именованные пороги для подсказки редактора, на отбор не влияют.

Матч получает приоритет по цепочке: переопределение локали → общий → по умолчанию. «Местные матчи» локали в телеграме — турниры, которые она подняла выше общего приоритета; опущенный для локали турнир местным не становится.

Диапазоны разнесены намеренно: крупные турниры сборных от 1100, элита клубных от 800, местные топ-лиги и кубки около 500, лиги мира от 100, вторые дивизионы около 50, дальше малые клубные (45), юноши (30), женщины (15) и 1 по умолчанию. Запас между ними большой специально: правка одного числа не перебросит турнир в соседний диапазон случайно. Раньше шкала была в тысячу раз крупнее (2 000 000 у чемпионата мира) — нули убраны, порядок не изменился.

### География локалей

Общая таблица одна на всех, но зрителю локали ближе свой регион: иранцу интереснее саудовская лига, чем чемпионат Исландии того же уровня. Это учитывается **переопределениями локали** по одному правилу:

| Уровень | Приоритет | Пример для Ирана |
|---|---|---|
| Свои лиги | 500–520 | Persian Gulf Pro League |
| Континентальные клубные турниры своего континента | 440 и 400 | AFC Champions League, AFC Cup |
| Сильные соседи | ≈335 (как Турция, Португалия) | Саудовская Аравия, Катар, ОАЭ |
| Остальной регион | ≈227–235 (выше Скандинавии и Исландии) | Узбекистан, Ирак, Казахстан, Азербайджан, Иордания, Армения, Кувейт, Таджикистан, Сирия |

Внутри уровня — по силе и без ничьих: шаг 3 (335, 332, 329), а где турниров много — 1–2, чтобы «регион» не опустился ниже Скандинавии (Allsvenskan, 224). **Поднимается только замапленный турнир**: без маппинга его матчи займут место в списке, а в купон не попадут. Континентальные клубные турниры Азии и Африки в общей таблице стоят на уровне КОНКАКАФ (375 и 300), а у «своих» локалей — выше.

`group` — прежний раздел турнира (сборные, еврокубки…). На отбор не влияет; нужен подписи «International» / «International Clubs» в телеграме и правилу «свой клуб локали» (группа `international_clubs`); редактор его не трогает.

### Порядок матчей внутри турнира: статусы команд

Порядок турниров задают приоритеты выше; внутри турнира матчи идут по **статусам команд** из `config/team_status.json` («топ», «сильная», «обычная» — умолчание для команды без записи). Файл правит вкладка «Приоритеты» заполнялки; рейтинг сборных бот сам не качает.

```json
{
  "teams": {"<team_id>": {"name": "Spain", "status": "top", "by": "rating"}},
  "eurocups": {"<league_id>": {"<team_id>": {"name": "Inter", "status": "top", "by": "manual"}}},
  "locales": {"turkey": {"league_id": 600, "own_clubs": [<team_id>]}},
  "rating": {"top": 20, "strong": 50},
  "top_bonus": {"top_pair": 60, "top": 30}
}
```

`teams` — сборные (статус один, из рейтинга ФИФА) и статус клуба **дома** — в турнирах его страны; `eurocups` — свой список у каждого турнира группы `international_clubs` (ключ — `league_id`): клуба в списке турнира нет — «обычная», из домашнего статус не выводится («Шахтёр» — топ в чемпионате Украины, обычный в Лиге чемпионов; «Рома» — топ в Лиге Европы). `status` — `top` / `strong` / `regular`; `by` — `rating` (из рейтинга ФИФА) или `manual` (поставил человек, обновление рейтинга его не трогает); `own_clubs` — клубы высшей лиги страны локали (`league_id` — какая лига «своя»); `rating` — границы мест рейтинга для страницы.

Правило (`_ordered`, `top_mark`):

- **топ-матч** — «топ + топ» или «топ + сильная» («сильная + сильная» — не топ-матч, остаётся в обычном пресете без надбавки);
- **свой клуб локали** — в турнире группы `international_clubs` матч клуба из `own_clubs` этой локали всегда топ-матч и стоит первым среди топ-матчей, с любым соперником; в своей лиге и внутренних кубках не действует;
- **надбавка топ-пресета** (`top_bonus`: `top_pair` — за «топ + топ» и свой клуб локали, `top` — за прочие топ-матчи; правится в шапке вкладки «Приоритеты»): топ-часть турнира получает её к приоритету турнира — по сильнейшему матчу — и встаёт в общий порядок дня по сумме, отдельным блоком; при равной сумме — выше обычного турнира. Первыми идут топ-матчи разных чемпионатов: при 60/30 «Реал — Барса» (475 + 60) выше «Арсенал — Вилла» (480 + 30), обе — выше остальной АПЛ. Деление на виджеты режет по непрерывным отрезкам турнира, поэтому поднятая топ-часть может уйти в Top Events без остатка. Нет чисел — 0, порядок прежний;
- внутри турнира сначала топ-матчи, затем остальные; в каждой части — старший статус пары, затем младший, затем **ранний матч выше**. Порядок турниров и деление на виджеты не меняются — турнир остаётся целым.

В файл списка (`data/*.json`, все разделы) матч получает `home_tier`, `away_tier` и у топ-матча — `top: true`, `top_reason` (`pair` / `own_club`); статусы — те, что действуют в турнире матча (в еврокубке — из его списка в `eurocups`); пока в файле статусов нет ни одной команды, этих полей нет. В Telegram — только новый порядок. Правка статуса действует со следующей сборки списков.

## Переменные окружения

Задаются в Settings → Secrets and variables → Actions:

| Переменная | Зачем |
|---|---|
| `HIGHLIGHTLY_API_KEY` | получение матчей |
| `TELEGRAM_BOT_TOKEN` | отправка отчёта |
| `TELEGRAM_CHAT_ID` | куда отправлять |

Имена должны совпадать точно — workflow обращается к ним как `secrets.HIGHLIGHTLY_API_KEY` и так далее.

Без любой из них прогон остановится с сообщением, какую переменную задать, а не с невнятным `KeyError`.

**Actions в новом репозитории может потребоваться включить** во вкладке Actions — иначе расписание не сработает.

## Локальный запуск

```bash
pip install -r requirements.txt
```

```bash
export HIGHLIGHTLY_API_KEY=<ключ>
export TELEGRAM_BOT_TOKEN=<токен>
export TELEGRAM_CHAT_ID=<id>
python -u match_report.py
```

Флаг `-u` важен: без него вывод буферизуется и печатается одним куском в конце, из-за чего по логам невозможно понять, на каком шаге тратится время. В workflow он уже прописан.

Пути к конфигу и `data/` считаются от расположения скрипта, так что запускать можно из любой директории.

## Только списки: `--lists-only`

coupon-filler заполняет купоны и на даты, которые бот не публикует (послезавтра и дальше). Списки на них он добывает этим же скриптом:

```bash
python -u match_report.py --lists-only --start 2026-09-25 --end 2026-09-27 --out ../coupon-filler/data
```

Отбор тот же, что у ежедневного отчёта — функция одна, чтобы купон не разошёлся с чатом. Отличия: ни Telegram, ни чистки `data/`, и нужен только `HIGHLIGHTLY_API_KEY`. Даты абсолютные, `--end` по умолчанию равен `--start`.

Если на дату матчей нет (или все раньше 07:00 по Минску), файлы на неё не пишутся, а скрипт выходит с кодом **3** — «матчей нет» отличается от поломки. Остальные даты диапазона при этом записываются.

Тесты — `python tests/test_lists_only.py` и `python tests/test_priorities.py` (приоритеты, «местные» в Telegram): Highlightly подменён, квоту они не тратят.

## Диагностика

В логах прогона есть тайминги: сколько заняла каждая страница выдачи Highlightly и каждая отправка в Telegram. Если прогон долгий — по ним видно, где именно.

Запросы к одной и той же дате кешируются на время прогона: донабор «перетёкших» матчей запрашивает послезавтра отдельно для Бразилии и Мексики, и без кеша этот день выкачивался бы дважды.

Ошибка отправки в Telegram больше не проходит молча — прогон падает с кодом ответа. Раньше протухший токен или битый Markdown означали, что скрипт отчитывается об успехе, `data/*.json` коммитятся, а в чат ничего не приходит.
